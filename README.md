# TaskHive — marketing website

A static, dependency-free marketing site for **TaskHive**, a technology-enabled business
support company providing flexible remote professionals to businesses in the UK and
internationally.

Plain HTML, one CSS file, one JS file. No build step, no framework, no package manager —
open `index.html` in a browser and it works.

## Brand

### Colour

Every brand value was sampled directly from the supplied logo artwork rather than guessed:

| Token | Hex | Sampled from |
| --- | --- | --- |
| `--honey-500` | `#FDBE02` | Hive mark, upper chevrons |
| `--amber-500` | `#FD9E01` | Hive mark, lower diamond |
| `--ink-900` | `#02152C` | "task" wordmark and tagline |

Supporting creams, slates and tints are derived from those three. Two extra tokens exist
purely for accessibility: `--amber-text` (`#A85F00`) is the darkened amber used wherever
amber appears as small text, and `--slate-500` was darkened to `#5C7089` so muted copy
clears WCAG AA. Never use `--amber-600` for body text — it fails contrast on light
backgrounds.

### Type

- **Figtree** (700–900) for headings, buttons and UI labels — geometric and rounded, in
  keeping with the logo's letterforms.
- **Inter** (400–700) for body copy.

Both load from Google Fonts with a system-font fallback stack, so the site still renders
sensibly if the font request fails.

### Logo assets

| File | Use |
| --- | --- |
| `logo-nav.png` | Mark + wordmark, no tagline — header |
| `logo-nav-light.png` | Same, recoloured for dark backgrounds |
| `logo-lockup.png` | Full lock-up including tagline |
| `logo-lockup-light.png` | Full lock-up for dark backgrounds — used in the footer |
| `logo-mark.png` / `logo-mark.svg` | Hive mark alone |
| `favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` | Browser and device icons |

The light variants were generated by recolouring the navy ink to white while preserving the
amber and the alpha channel. `logo-mark.svg` is a hand-built vector reconstruction of the
mark (hexagon sliced into three chevron layers with a yellow→orange gradient) for crisp
rendering at favicon sizes.

### Design motifs

The hive is carried through the whole system: hexagonal icon tiles, hexagon avatars and
step numbers, a honeycomb background texture (inline SVG data URI, no image request), and
chunky "pressable" buttons with an offset shadow.

## Running it

Any static host will do. Locally:

```bash
npx http-server -p 8080 -c-1
# or
python3 -m http.server 8080
```

Then open <http://localhost:8080>. To deploy, upload the repository root as-is to Netlify,
Vercel, Cloudflare Pages, GitHub Pages or ordinary shared hosting.

## Before this goes live

Everything below is **placeholder content written to demonstrate the design**. It reads as
plausible, which makes it easy to miss — replace it with real figures before launch.

**Proof points and statistics** — all invented:
- Home hero: "4.9 / 5", "200+ growing businesses", "5 days average match time", "Up to 40% saved vs. in-house hire"
- Home stats band: "12,400+ hours", "5 days", "4.9/5", "20+ sectors"
- Vetting funnel figures on the home page (2,480 → 38) and the same numbers repeated on `about.html`
- "96% tasks on time", "1.4h avg. response", "18 processes documented"

**Testimonials** — the three quotes on `index.html` (Hannah B., Daniel O., Priya R.) are
written examples, not real clients. Replace them, or remove the section, before publishing.

**Pricing** — £380 / £1,020 / £2,400 and the 10% annual discount are illustrative. The
in-house cost comparison on `pricing.html` states its assumptions inline (£32,000 FTE at
0.375 FTE, 15% recruitment fee, statutory minimum pension); check those against your own
numbers.

**Contact details** — `hello@taskhive.co.uk`, `+44 (0)20 8000 0000` and "London, United
Kingdom" appear in the footer and on `contact.html`.

**Links that go nowhere** — privacy policy, terms, cookie policy and modern slavery
statement in the footer, the privacy links inside both form consent checkboxes, and the
four social icons all point at `#`.

**Domain** — `https://www.taskhive.co.uk/` is used in every `<link rel="canonical">`, the
Open Graph tags, the JSON-LD block, `robots.txt` and `sitemap.xml`. Update it everywhere
if the real domain differs.

**Forms have no backend.** Both forms carry `data-demo-form`; `main.js` intercepts submit,
validates, and shows a confirmation message without sending anything. To wire them up,
remove that attribute and add a real `action`/`method`, or point them at a form service
(Formspree, Netlify Forms, HubSpot). The validation and status markup can stay.

**Photography.** The site is deliberately illustration-led — hexagons, honeycomb texture
and CSS/SVG "product" visuals rather than stock photos. If you want real photography, the
natural slots are the hero (replace the `.board` block in `index.html`), the
`.feature-row__media` cards, and the testimonial avatars (`.hex` elements already accept an
`<img>` child and will crop it to the hexagon).

## Notes for whoever picks this up

**Editing.** Header and footer markup is duplicated across the six pages, which is normal
for a static site — a change to navigation means the same edit six times. The active nav
link is set at runtime by `main.js` from the current filename, so no per-page markup is
needed for that.

**Components** worth knowing about in `styles.css`:
- `.btn` variants use a `--btn-lift` custom property for the pressable offset shadow, so
  size modifiers never clobber the ghost variants' ring.
- `.feature-row--reverse` flips a two-column row on desktop while keeping the copy first in
  the DOM, so the reading order stays correct when it stacks on mobile.
- A light card placed inside a `.section--ink` needs no special handling: `.mini`,
  `.form-card`, `.card--cream` and `.card--honey` already reset their text colour.
- `.honeycomb-bg` and `.bloom` are decorative and `pointer-events: none`.

**Accessibility.** Skip link, landmarks, labelled forms, `aria-expanded` on the drawer,
dropdown and accordion, arrow-key support on the roles tabs, `aria-current` on the active
nav link, visible focus rings, and a `prefers-reduced-motion` block that disables every
animation. All text was audited against WCAG AA contrast on both light and dark surfaces.

**Progressive enhancement.** Scroll-reveal animation is scoped to a `.js` class set by a
small inline script in each `<head>`. With JavaScript unavailable the whole page renders
normally rather than staying at `opacity: 0`.

**Browser support.** Modern evergreen browsers. Uses CSS nesting-free plain CSS, custom
properties, `clamp()`, `aspect-ratio`, `clip-path` and `grid-template-rows` transitions for
the accordion.
